# Card Grid Implementation Plan

> **Status: Superseded. Do not execute this plan.**
>
> The instructions and checklists below preserve the original implementation
> approach, not the current code. See the [current design](../specs/2026-11-02-card-grid-design.md)
> for the implemented behavior. Private values now use page metadata and
> field-level Lambda filtering, not a separate resources block/index or
> browser-side authentication and resource merging. The shared cache accepts
> endpoints only, and empty grids preserve neighboring content.

> **For agentic workers:** REQUIRED SUB-SKILL: load
> `.ai/skills/test-driven-development/SKILL.md` and follow red-green-refactor
> for every task in this plan. `.ai/skills/create-new-block/SKILL.md` governs
> the two block scaffolds, and `.ai/skills/stylesheet-conventions/SKILL.md`
> governs their CSS. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `card-grid` into a data-driven block that generates one
`card-grid-item` per component page from a roll-up query index, and add the
`card-grid-resources` block that carries each component's private steward,
design-resource, and contact values.

**Architecture:** A shared fetch cache in `scripts/utils/` serves JSON indexes
with in-flight request deduplication. `card-grid` reads an authored config
table, requests the roll-up index through that cache, filters rows, derives a
status for each row from `deps/status-index.json`, and renders one item per
row through a renderer module that `card-grid` owns. For an authenticated
viewer, `card-grid` additionally requests an access-denied resources index and
merges the private values onto the matching items by path. `card-grid-resources`
renders the same three values on the component page itself and relies on
`filterAudienceBlocks` in the Lambda to strip them at the edge for anonymous
visitors. Two Lambda path lists gain entries so the roll-up index is row
filtered and the resources index is denied outright.

**Tech Stack:** Node.js 24, npm, `@web/test-runner`, `@esm-bundle/chai`,
`@playwright/test`, `@axe-core/playwright`, native CSS nesting.

**Design reference:** `.ai/docs/specs/2026-11-02-card-grid-design.md` records
the decisions, the measured index data, and the known risks. This plan does not
restate the rationale for any decision.

**TDD:** No exception is approved for this plan. Every task adds production
code and begins with a failing test. Per `AGENTS.md`, an unattended agent must
not approve its own TDD exception; stop and ask if a step appears to need one.

**Commit policy:** Ask before committing. Do not push, and do not open a pull
request without a direct request.

## Blocking prerequisites

The block renders correctly only after the content and index work in
`.ai/docs/specs/2026-11-02-card-grid-design.md` is complete. Tasks 1 through 7
can all be built and tested against fixtures and mocks before then. Do not
treat the feature as releasable until each item holds:

- [ ] Per-page card artwork exists through `card-image` overrides or suitable
      existing `image` values. The measured index returned one placeholder URL
      for all 91 rows.
- [ ] `subject`, `card-title`, `card-description`, `card-image`, `team`,
      `category`, and `behavior` are columns on the roll-up index, after a
      reindex.
- [ ] `behavior` has an agreed definition and value set.
- [ ] The private resources index exists and its target sits under a denied
      prefix.
- [ ] `/web/swc/components/patterns/conversational-ai` has a title and a
      description, or patterns placement is resolved.

## Assumptions to confirm before Task 4

The authored config table keys are taken from the concept screenshot and are
not yet confirmed. Task 4 reads them by label text rather than row position, so
changing or adding a key is a one-line change.

- Index selector: `content`, confirmed — `web`, `mobile`, or `patterns`, each
  naming the index that backs the grid. It selects the endpoint and does not
  filter rows.
- Filter keys: `subject`, `team`, `category`, `implementation`
- Limit key: `count`, defaulting to every matching row
- Rendered per card: `card-image` (falling back to `image`), `card-title`,
  `card-description`, implementation label, status badge, and private values
  for an authenticated viewer
- Image URLs resolve against each indexed page's `path`, not the grid page.
- Available for filtering but not rendered: `subject`, `team`, `category`,
  `behavior`

### Task 5: Accessibility coverage for `card-grid`

> Task 4 replaced the block's authored contract, so the committed fixture's
> literal cards stopped producing `.card-grid-item` and all three scans timed
> out in `gotoBlock`. This task restored them.
>
> **`toMatchAriaSnapshot` is a subset match.** A placeholder that happens to
> match the real tree, such as a bare `- list`, passes and is never rewritten,
> leaving a test that asserts nothing. `--update-snapshots` does not rewrite an
> inline template either. Take the expected tree from the **`+ Received`** side
> of a deliberate failure, not from the page snapshot in `error-context.md`:
> the page snapshot keeps `generic` wrappers and splits adjacent inline spans,
> while a locator-scoped snapshot flattens the wrappers and joins the spans.
>
> The forced failure must still be valid snapshot syntax. A bare hyphenated
> word such as `- FORCE-REGENERATE` is a parse error, which reports no diff at
> all; an absent but well-formed node such as `- heading "no such heading"`
> mismatches and prints the received tree.
